# Change the database schema

1. Edit the SQLAlchemy models in `api/src/immo_paris/db/models.py` (the source of truth).
2. Generate a draft: `uv run --directory api alembic revision --autogenerate -m "<imperative summary>"`.
3. Review the generated file in `api/migrations/versions/` line by line:
   - A rename appears as `drop_column` + `add_column` (**data loss**): replace it with
     `op.alter_column(..., new_column_name=...)` or `op.rename_table(...)`.
   - Autogenerate does not detect changes to CHECK constraints, computed columns, views,
     extensions or server defaults: write those operations by hand (`op.execute(...)` for
     raw SQL).
   - A new `NOT NULL` column on a populated table: add it nullable, backfill it with
     `op.execute("UPDATE ...")`, then `op.alter_column(..., nullable=False)`.
   - Index on a large existing table: consider `postgresql_concurrently=True` inside
     `with op.get_context().autocommit_block():`.
   - `downgrade()` must exactly reverse `upgrade()`.
   - Remove the "commands auto generated by Alembic" comments.
4. Apply it: `uv run --directory api alembic upgrade head`.
5. Check reversibility: `uv run --directory api alembic downgrade -1`, then `uv run --directory api alembic upgrade head`.
6. Check models and database are in sync: `uv run --directory api alembic check`.
7. Run the full definition of done (see api/CLAUDE.md), then commit the model change and its
   migration **in the same commit**.

Never edit a migration that has been applied outside the local machine: write a new one.
